Step 1: Data Preparation & Offline Knowledge Graph IndexingBefore running any queries, convert your text documents into an Entity-Document Knowledge Graph.Document Chunking: Split raw documents into text passages (e.g., 200–300 words each). Give each chunk a unique ID (chunk_1, chunk_2).Entity & Edge Extraction: Run an NLP model (spaCy en_core_web_sm or GLiNER) across all text chunks to extract named entities (e.g., Christopher Nolan, Inception, Oscar).Graph Assembly (NetworkX):Nodes: Add extracted entities as Entity Nodes and passages as Document Nodes.Edges: Draw an edge between Entity Node A and Entity Node B if they co-occur in the same chunk. Link each Entity Node directly to its corresponding Document Node.Save Graph State: Export the graph object to disk using pickle or json.Step 2: Query Anchor Extraction (Online Phase 1)When a user asks a question, extract search anchors deterministically without generating fill-in-the-blank hints.Input Query: "Did the director of Inception win an Oscar before 2010?"Deterministic Extraction: Run spaCy NER and Dependency Parsing on the query string.Anchor Output: Extract key entities directly: Anchors = ["Inception", "director", "Oscar", "2010"].Step 3: Subgraph Traversal & Multi-Hop Path RetrievalTrace multi-hop connections across the knowledge graph to protect intermediate "bridging" evidence.Anchor Mapping: Match the extracted query string anchors directly to their corresponding nodes in the NetworkX knowledge graph.Path Traversal (BFS / Shortest Path): Run a Breadth-First Search up to 2 hops to find edges connecting Anchor $A$ to Anchor $B$.Example Path: Inception $\rightarrow$ (directed_by) $\rightarrow$ Christopher Nolan $\rightarrow$ (won) $\rightarrow$ Oscar.Extract Bridging Documents: Collect all Document Nodes connected along these active traversal paths. This guarantees intermediate evidence (like Christopher Nolan) is included.Step 4: LLM Forward Pass & Attention Matrix Extraction (Phase 2)Pass the candidate text chunks into a open-weights model (e.g., Meta-Llama-3-8B-Instruct or Mistral-7B) on GPU to inspect inner attention scores.Input Formulation: Construct a single prompt containing your Query Anchors followed by the Candidate Chunks.Forward Pass Execution: Run PyTorch forward pass with output_attentions=True enabled:Pythonoutputs = model(**inputs, output_attentions=True)

Layer-Weighted Scoring: Extract the attention weights from intermediate transformer layers (typically layers 12–24 in 32-layer models). Measure how strongly each context token attends back to the query anchor tokens.Step 5: Dynamic Density-Based PruningFilter out low-attention background noise without relying on rigid static sentence cutoffs.Token Importance Calculation: Assign an attention score $S_i$ to each token in the candidate context based on its multi-head attention weight toward the query anchors.Adaptive Thresholding: Calculate the mean $\mu$ and standard deviation $\sigma$ of context token scores. Keep only tokens where:$$S_i > (\mu - \alpha \cdot \sigma)$$Topological Reordering: Reassemble the surviving high-attention tokens back into their original graph-traversal order ($Hop_1 \rightarrow Hop_2$).Step 6: Final Answer GenerationFeed the compressed context to the generator LLM.Prompt Assembly: Combine the original user question with the compressed, topological context.Final Pass: Execute standard text generation (model.generate()). Because surrounding syntactic filler is pruned, the LLM processes context faster and produces an accurate, hallucination-free answer.Suggested Execution TimelineWeeks 1–2: Build Step 1 (Document Indexing & NetworkX Graph creation).Weeks 3–4: Implement Steps 2 & 3 (spaCy query parsing + path traversal).Weeks 5–6: Implement Steps 4 & 5 (HuggingFace attention extraction + dynamic pruning).Weeks 7–8: Evaluate accuracy against HotpotQA and finalize thesis report.
